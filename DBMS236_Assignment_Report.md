## 1. System Proposal
This project is an Enterprise Web Application designed to manage e-commerce inventory, customer records, and order processing efficiently. It uses a Python web framework for server-side logic and connects to an Oracle Database backend (`XEPDB1`) to perform operations reliably.

---

## 2. Overview of the Application
The application provides full CRUD (Create, Retrieve, Update, Delete) capabilities over multiple related database entities. It features a web-based graphical user interface (GUI) for interactive data manipulation and executes background automated tasks for real-time inventory adjustments.

### Key Functionalities
- **CRUD Operations:** Full record management for `CUSTOMERS`, `PRODUCTS`, and `ORDERS`.
- **Entity Navigation Queries:** Retrieve specific details across connected tables (e.g., all orders placed by a specific customer).
- **Complex Analytical Queries:** Multi-table joins combining customer, product, and order details.
- **Asynchronous Background Processing:** Automated background tasks updating product stock levels upon order confirmation.

---

## 3. System Architecture & Interaction
The application follows a standard three-tier architecture:

1. **Presentation Layer (Client):** Web GUI built with HTML, CSS, and web templates.
2. **Business Service Layer (Server):** Python web application managing business logic, routing, DTO serialization, and background task queuing.
3. **Data Access Layer (Database):** Oracle Database accessed via SQLAlchemy ORM / `oracledb` drivers using connection string `localhost:1521/XEPDB1`.

---

## 4. Design of Web & Business Components

### Web Components
- **Framework:** Flask / Django
- **Templates & REST APIs:** Renders HTML views for users and exposes REST endpoints for asynchronous operations.

### Business Service Layer
- **Data Transfer Objects (DTOs):** Serializes database records into structured data formats for web transfer.
- **Business Rules:** Validates customer inputs, processes transactions, and verifies stock availability before database commit.

## 5. Database Access & Design

### Database Tables Schema

#### 1. CUSTOMERS
| Column Name | Data Type | Constraint |
| :--- | :--- | :--- |
| `customer_id` | NUMBER | PRIMARY KEY (GENERATED BY DEFAULT AS IDENTITY) |
| `name` | VARCHAR2(100) | NOT NULL |
| `email` | VARCHAR2(100) | UNIQUE, NOT NULL |
| `phone` | VARCHAR2(20) | NULLABLE |

#### 2. PRODUCTS
| Column Name | Data Type | Constraint |
| :--- | :--- | :--- |
| `product_id` | NUMBER | PRIMARY KEY (GENERATED BY DEFAULT AS IDENTITY) |
| `product_name`| VARCHAR2(100) | NOT NULL |
| `price` | NUMBER(10,2) | NOT NULL |
| `stock_quantity`| NUMBER | NOT NULL |

#### 3. ORDERS
| Column Name | Data Type | Constraint |
| :--- | :--- | :--- |
| `order_id` | NUMBER | PRIMARY KEY (GENERATED BY DEFAULT AS IDENTITY) |
| `customer_id` | NUMBER | FOREIGN KEY REFERENCES CUSTOMERS(`customer_id`) |
| `product_id` | NUMBER | FOREIGN KEY REFERENCES PRODUCTS(`product_id`) |
| `order_date` | DATE | DEFAULT SYSDATE |
| `quantity` | NUMBER | NOT NULL |

### Entity-Relationship (E-R) Diagram
### Class Diagram Description
